# 이트너스몰 배송운영 관리

행사성 주문에서 반복되는 **미주문자 확인 → 1차 안내** 업무를 줄이기 위한 사내 운영 지원 MVP.
이트너스몰을 대체하지 않으며, 실제 API 연동이나 외부 이메일 발송 없이 가상 데이터로
전체 업무 흐름을 시연한다.

```
주문 데이터 등록 → 미주문자 자동 선별 → 마감일·D-day 자동 계산
→ 오늘 안내 대상 자동 분류 → AI 안내메일 초안 작성 → 관리자 최종 확인
→ 발송 직전 재확인 → 1차 안내 발송 → 이력 저장 → 대시보드 자동 갱신
```

## 실행

```bash
cd delivery-management
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe app.py
```

http://127.0.0.1:5050 접속. 첫 실행 시 `instance/delivery.db`가 자동 생성되고
데모 데이터가 채워진다.

## 데모 계정

| 구분 | 아이디 | 비밀번호 |
|---|---|---|
| 관리자 | `admin` | `admin1234` |
| 조직원 | `employee01` ~ `employee10` | `employee1234` |

조직원 중 일부는 자료 오류(이메일 누락/형식 오류)가 섞여 있어, 안내 대상에서
자동 제외되는 것을 확인할 수 있다.

## MVP 범위에서 의도적으로 다르게 구현한 부분

원본 요청서와 다른 판단을 내린 지점을 정리한다. 나중에 실제 서비스로 확장할 때
참고할 수 있도록 이유를 남긴다.

- **AI 안내메일 생성은 실제 LLM API를 호출하지 않는다.** `mailwriter.py`가 행사·수신자·
  마감일 정보를 규칙 기반으로 조합해 자연스러운 문장을 만든다. API 키 없이도 전체
  플로우를 바로 시연할 수 있고, 반환 형태(제목·본문 문자열)만 유지하면 나중에 실제
  API 호출로 교체해도 호출부를 손댈 필요가 없다.
- **실시간 갱신은 Flask-SocketIO 대신 `fetch()` 폴링(5초)만 구현했다.** 요청서도
  SocketIO를 "가능한 경우"로 명시해 필수는 아니었고, 폴링만으로 대시보드·주문
  현황·발송 이력의 자동 갱신을 충분히 시연할 수 있다.
- **주재지별 배송 소요일은 별도 테이블(`DestinationLeadTime`)로 분리했다.** 원본
  스키마에는 없었지만, "관리자가 사전에 설정할 수 있도록 한다"는 요구를 만족하려면
  어딘가에 저장하고 편집 화면이 있어야 해서 추가했다. 행사 관리 화면 하단에서
  관리한다.
- **주문완료 처리 버튼을 주문 현황 화면에 넣었다.** 실제로는 이트너스몰 쪽 데이터가
  들어오는 자리이지만, MVP는 가상 데이터만 다루므로 관리자가 직접 상태를 바꿀 수
  있어야 대시보드 실시간 갱신과 "발송 직전 재확인" 기능을 눈으로 확인할 수 있다.

## 핵심 계산 로직

`models.py`의 `EmployeeOrder`가 담당한다. 계산값(마감일·D-day·우선순위·자료 오류)은
컬럼에 저장하지 않고 그때그때 계산한다 — 저장해 두면 원본 값이 바뀌었을 때 갱신을
깜빡해 오래된 값이 남을 수 있기 때문이다.

```
주문 마감일 = 수령 희망일 − 주재지별 배송 소요일
D-day = 주문 마감일 − 오늘

D ≤ 0   → 즉시 확인
D 1~3   → 우선 안내
D 4~7   → 일반 안내
D ≥ 8   → 안내 예정

오늘 안내 대상 = 미주문 AND 자료 오류 없음 AND (즉시 확인 OR 우선 안내)
```

## 발송 직전 재확인 (요청서 17번 항목)

`/admin/notifications`의 2단계 흐름이 그대로 구현이다.

1. **생성** — 선택한 대상(또는 자동으로 오늘 안내 대상)의 초안을 만든다. 이 시점에
   이미 주문했거나 자료에 문제가 있는 사람은 초안조차 만들지 않는다.
2. **재확인** — "발송 대상 확인" 버튼을 누르면, 초안이 만들어진 뒤 그 사이 주문을
   완료한 사람을 찾아 발송 대상에서 제외한다.
3. **발송** — "1차 안내 발송"을 눌러도 한 번 더 같은 확인을 거친 뒤 확정한다.
   재확인을 건너뛰고 바로 발송을 눌러도 안전하다.

## 권한 분리

- 관리자 전용 라우트는 `@admin_required`로 막는다. 조직원이 URL을 직접 입력해도
  403을 반환한다.
- 조직원의 모든 조회는 `user_id`로 자기 것만 걸러진다. 다른 조직원의 정보는
  서버 쿼리 단계에서부터 아예 가져오지 않는다.
